# RELYR for Mac — 試用版 0.2.0

Apple Silicon、macOS 13以降向けのSwiftネイティブ試用版です。
Windows版の3列エディターとActionドラッグ操作をMac向けに実装しています。
Windows版の全機能を移植したものではありません。詳細な引き継ぎ基準は `WINDOWS-PARITY.ja.md` を参照してください。

## ビルド

Xcode Command Line Toolsが必要です。未導入ならターミナルで `xcode-select --install` を実行します。
リポジトリのルートで実行してください。

```sh
# 初回のみ。以後は同じ署名を保持するため再作成しない
python3 macos/sign-local.py --initialize
bash macos/build.sh
bash macos/install-local.sh
open '/Applications/RELYR Mac Trial.app'
```

アプリ、ZIP、チェックサム、コンパイラーキャッシュ、テスト用設定とプレビューは `.verification/macos-build/` に生成します。ローカルで使うアプリは `/Applications/RELYR Mac Trial.app` に統一します。既存のアプリを更新するときは、Dockの固定先を保つため、同じアプリの中身を入れ替えます。検証用のコピーに適用する場合は `bash macos/install-local.sh --verification` を使います。ビルド中に起動中のアプリは変更しません。インストールは通常終了を待ち、終了できない場合は上書きせず停止します。
ビルドは517件のコアチェック、不正設定、ネイティブイベント生成、排他ロック、画面・保存・ドラッグ先処理・Undoを検証します。
テストはキーイベントを送信せず、入力変換を有効化しません。実際のキー配送やマウスドラッグの成否は別の検証です。
このMacで継続利用する固定のローカル証明書で署名します。`.local-signing/` は秘密鍵を含む専用キーチェーンです。Git・ZIPに含めず、ビルド間で削除・再生成しないでください。検証出力の `.verification/` とは別に保持します。鍵がない場合はビルドを停止し、仮署名へ戻しません。システムの証明書信頼設定は変更しません。
旧アドホック署名からの移行時だけ、macOSが許可の再登録を求める可能性があります。以後は同一の識別条件を保持することを、内容の異なる2つのアプリの相互署名検証で確認します。実際のmacOS許可継続は別途確認が必要です。Developer ID署名・公証は未実施で、他のMacへの一般配布向けではありません。
署名の根拠: [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)、[Apple TN2206](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)。

## 画面と割り当て

1. 左側の「デフォルト」「Space」「CapsLock」「右クリック」「戻る」「進む」「メニューバー」を選びます。
2. 右側の「Actionを選択」を開きます。
3. カテゴリから「基本操作」「キー」などを選び、Action行を中央のキーへドラッグします。
4. ドラッグ中の上半分 **TAP** または下半分 **HOLD** へドロップします。HOLD時間は概要から変更できます（50〜10000ms）。ホイールにはHOLDを割り当てません。
5. 変更はすぐ保存されます。直後の「元に戻す」、上部の↶/↷、Command+Z / Command+Shift+Zで変更を戻せます。

例えばSpaceレイヤーのCへ「コピー」をドロップすると、Space+C → Command+Cになります。
アプリ起動、文字列、URL、任意ショートカットは、ドロップ後のダイアログで値を指定します。
キャンセルした場合は元の設定を維持します。

キーをクリックすると右側に現在の割り当て概要を表示します。概要のActionもドラッグで移動でき、OptionまたはControlを押しながらならコピーできます。
Command／Controlクリックで個別選択、Shiftクリックで範囲選択し、選択内のキーへドロップすると一括で割り当てます。
保護されたSpaceや物理修飾キーは割り当て元にできません。

Actionの星を押すとお気に入りに登録します。最近使ったものには、実際に保存が成功したActionが入ります。
検索は名前・カテゴリ・出力値を対象にします。「使用中」は保存済み割り当てから生成します。
上部の☷で既存割り当ての一覧を開けます。ライト／ダークは右上の太陽／月で切り替えます。

## 入力の開始と停止

初期設定では起動時はOFFです。「設定」の「アクセシビリティを許可…」からRELYR Mac Trialを許可し、
左下の「入力停止中」または設定内の「有効にする」を押して開始します。
停止は同じ場所、メニューバー、または **Control + Option + Command + Escape**。
ウィンドウを閉じても常駐します。Command+Qまたはメニューバーの「終了」で終了します。

「設定」の「サンプル追加」で、編集中のプロファイルにSpace+A/D/W/S → 左/右/上/下を追加できます。既存割り当ては上書きしません。
Space単独は離したときに空白1つ、未割り当てキーとの組み合わせはSpaceを先に復元して通常入力に戻ります。
物理修飾キーは出力に引き継ぎます。Command+Spaceなど、修飾キーを先に押す組み合わせも維持します。
パスワード入力・スリープ・画面ロック・一時的な監視中断は「一時停止」と表示します。元々入力ONだった場合のみ、復帰後にすべてのキーとボタンが離されると自動再開します。手動停止後はOFFのままです。再起動時の復元は下記の設定で選べます。権限の一時喪失や連続タイムアウトでも有効にする設定を保持し、許可・通常入力が戻れば自動再接続します。再接続の失敗は最大5秒間隔で再試行します。

## マウスレイヤー

右クリック・戻る・進むボタンを押しながら、割り当てたキー／子ボタン／ホイールを操作します。
そのレイヤーに割り当てがあるときだけ押下を保留し、使わず離すと元のクリックを復元します。
レイヤー元を先に離しても、押していた子キーの出力を対応する解放まで保持します。
未割り当ての子クリックは通過し、通常レイヤーの左クリックとレイヤー元自身への割り当ては禁止します。
未使用の右ボタンでドラッグした場合はDown・移動・Upを復元します。各ボタンをOSのマウスイベントとして受信することが前提です。
イベント順序・設定保存・停止時解放は無送信テストで検証しています。実マウスと他アプリへの配送は未検証です。

## プロファイル

上部のプロファイルは編集対象です。左の「プロファイル」から作成・複製・名前変更・削除できます。
「手動使用」は入力の実行対象で、編集対象とは独立しています。
「対象アプリを追加…」でアプリを関連付け、「アプリに合わせて自動切替」をONにすると前面アプリで切り替わります。
関連付けは正確なbundle IDで判定し、未登録アプリは標準を使用します。マウス位置では切り替えません。
標準プロファイルは削除できません。別プロファイルの削除では、そのプロファイルを参照するDeckボタンも削除されます。

## Deckパネル

「モニターを追加…」から「画面の輝度」を追加できます。内蔵画面を優先し、内蔵画面がない場合はメイン画面を対象にします。読み取り非対応の画面では「—」と表示します。各モニターは専用アイコンで区別でき、音量・輝度・バッテリーは残量バー、CPU・メモリ・通信量は推移グラフを表示します。

キーを選び、右側の「Deckへ追加」で既存割り当てを追加できます。
左の「Deckパネル」で編集し、「Deckを表示」で実行用の小さいウィンドウを表示します。
同じActionライブラリから既存のDeckボタンへドラッグすると、参照元のキー割り当ても更新されます。
番号付きの空きマスへドラッグすると、キー割り当てと独立したDeck専用Actionを追加します。列数1〜18、最大324ボタン、名前の表示、複数選択と色変更・コピーに対応します。
右クリックで名前変更・前後への移動・削除ができます。Deckから削除しても元のキー割り当ては残ります。

実行用Deckは非アクティブ型です。先に操作したいアプリをクリックしてからDeckを押してください。
入力OFFの間も登録・編集・表示は可能ですが、ボタンからの実行は停止します。
キーから追加したDeckボタンは登録元のプロファイルとキーを参照します。Deckの「プロファイル別に切り替える」を有効にした場合は、前面アプリに対応するDeckバリエーションを表示します。
文字列送信は対象アプリの切替、別のキー入力・クリック・修飾キー操作、停止、セキュア入力で中断します。
すでに入力された文字は取り消しません。URLはHTTP(S)のみ、文字列は最大4096 UTF-16コード単位です。

## ログイン時の自動起動

「設定」の「ログイン時に自動起動」でmacOSへの登録を切り替えます。「起動時に入力を有効にする」をONにすると、ログイン後やアプリの再起動時に入力監視を開始します。アクセシビリティ許可待ちや保護された入力中は待機し、利用可能になれば再開します。手動停止・緊急停止はその実行中は維持し、次のアプリ起動時にはこの設定に従います。

## 設定と復旧

- 設定：`~/Library/Application Support/io.github.zitan-source.relyr.mac.trial/configuration.json`
- エディターの履歴・お気に入り・テーマ：同フォルダの `editor-library.json`
- 入力内容のログや外部送信はありません。文字列Actionの内容は設定に平文で保存されます。
- 設定画面の読み込み／書き出しはMac版専用JSONです。Windows設定は読み込めません。
- 読み込み前に `configuration.before-import-<ID>.json` へ元データをバックアップし、読み込み後はOFFにします。
- 0.1.0設定は初回保存時に `configuration.v1.backup.json` を残して移行します。
- 設定破損・未対応形式を検出した場合は上書きせず、入力と編集を無効にします。正常な設定の読み込みで復旧できます。
- インポート／エクスポートにはエディター専用の履歴・テーマは含みません。

## 試用版の制限

自動更新、Intel版は未対応です。CapsLockレイヤーはF13を入力元とし、OSのCapsLock割り当てを自動変更しません。
上部のJIS／USで配列表示を切り替え、保存できます。JISの¥・_・英数・かなとテンキーも割り当てできます。OSの入力ソースは変更せず、割り当ては物理キーコードを保持します。既存設定に配列情報がない場合は従来のUS表示を保持します。
低レベル入力を独自処理するアプリの互換性、OS全体向けのDeckショートカットは保証しません。
アプリの設定／プロファイル／Deckは既存のMac版モデルを使用し、Windowsソースやインストーラーを変更しません。

## メニューバーとウィンドウAction

Windows版の「タスクバー」は、Mac版では画面上部のメニューバーとして扱います。
Dockはこのレイヤーの対象ではありません。表示中のメニューバー領域上で、右ボタンHOLD、中ボタン、戻る／進むボタン、ホイールに割り当てられます。
左ボタンのTAP/HOLDと右ボタンのTAPは予約済みです。右HOLDの短押しは元の右クリックを復元します。
自動で隠したメニューバーの一時表示は未検証です。

Actionの「ウィンドウ」には最大化、最大化／元に戻す、最小化、復元／最小化、閉じる、左右半分、上下左右のモニター移動、すべて最小化／元に戻すがあります。
最大化はフルスクリーン化せず作業領域へ配置します。元の位置・サイズは実行中のメモリに保持します。
設定で使用中／カーソル下を選択できますが、メニューバー経由では使用中のウィンドウが対象です。
Dock・メニューバーはウィンドウ操作対象から除外し、対象不明時は別ウィンドウに切り替えません。
フルスクリーン中の最大化トグルはフルスクリーンを解除して元のサイズへ戻します。左右半分への配置は解除後に同じウィンドウへ適用します。解除とサイズの安定を最大5秒待ち、対象が閉じた場合や解除を拒否した場合は中止します。アプリの最小幅によっては正確な半分に縮小できません。
アクセシビリティAPIでサイズ変更を受け付けないアプリはエラー表示します。
自動検査は模擬バックエンドを使用し、他アプリの実ウィンドウを移動・閉じる操作は実行しません。


## Controlキーレイヤー

左側の「Control」を選び、ActionをキーのTAP/HOLDへ配置します。
Controlを押した状態で割り当てたキーを押すと、そのActionを実行します。
「キー」カテゴリの「?」をJのTAPへドロップするとControl＋JでShift＋/を出力します。
JIS/USの通常入力で「?」になりますが、日本語IMEのモードによって表示が変わる場合があります。
未割り当ては通常のControl操作を通し、マウスのControl＋クリックも変更しません。
Controlは左右を区別しません。既存F13/CapsLock設定は自動変換せず保持します。
出力からレイヤー元のControlだけを除き、Actionに明示したControlは保持します。
自動テストは無送信で確認しており、物理入力配送は別途確認が必要です。


## 音量・スクリーンショット・Mac用Action

Actionカテゴリの「音量」から音量を上げる／下げる（6.25%刻み）、消音／解除を選べます。
音量を上げると消音も解除します。Core Audioで制御できない出力機器はエラーを表示します。
「スクリーンショット」には全画面、範囲選択、画面収録パネル、全画面／範囲をクリップボードへコピーがあります。
Macの標準ショートカットを使うため、OS側でショートカットを変更・無効化している場合は動作が異なります。
範囲選択や画面収録の開始はMacのパネルで操作してください。DeckからもOS向けのイベントとして送ります。
「デスクトップ」には左右のSpace切り替え、Mission Control、アプリウィンドウ一覧、Spotlightがあります。
Actionの「ウィンドウ」に「ウィンドウを左／右のデスクトップへ移動」と「ウィンドウをデスクトップ1〜16へ移動」を追加しました。ウィンドウを移動した後、同じデスクトップへ切り替えて対象ウィンドウを前面にします。左右は同じモニター内の通常デスクトップ、番号はMission Controlの表示順（全画面Spaceを除く）です。移動先は先にMission Controlで作成してください。OSのControl＋数字の設定は不要です。フルスクリーンは解除してから移動します。全デスクトップに固定したウィンドウは対象外です。

この機能は動的に検出するmacOS内部機能を利用します。このMac（macOS 27.0.1）では検証用ウィンドウの往復移動を確認しました。OS更新で利用できなくなる可能性があり、非対応・移動拒否・結果未確認の場合はエラーを表示します。OSの保護設定は変更しません。
「基本操作」にはFinderの移動貼り付け、タブ、新規ウィンドウ、印刷なども追加しています。

## マウスホイールの方向

各レイヤーのキーボード下に「このレイヤーでマウスホイールの方向を反転」があります。
通常のマウススクロールを常に反転する場合は「デフォルト」でONにします。入力変換ONの間だけ適用します。
左右・上下のホイール方向を反転し、割り当てたホイールActionの方向判定にも反映します。
設定はレイヤーごとに保存され、全プロファイル共通です。Undoで戻せます。
連続スクロールを除外するため、トラックパッドの方向・慣性は変更しません。
ただしOSが連続スクロールとして通知するマウス（Magic Mouseや一部の滑らかなスクロール）も対象外です。
機器名での完全な判別や、機器ごとの設定ではありません。

## 追加マウスボタンと修飾クリック

設定の「ボタンを押して確認・割り当て…」で、枠内で押したボタンのmacOS番号と現在の名称を確認できます。Fn1などの名前を付け、編集するレイヤーを選べます。追加ボタン番号3〜31はキーボード画面の「追加マウスボタンを選択…」からも編集できます。通常の左クリックとメニューバーの左クリックは引き続き保護されます。

ELECOM等がボタンをキーに変換している場合は受信したキー名・コードを表示します。変換をOFFにしてから確認してください。本体のFn表記を推測して割り当てることはしません。OSにマウスイベントを出さない独自ボタンへのHIDドライバー対応は未実装です。

Actionの「マウス」にShift／Control／Command／Option＋左クリックと左・右・中央クリックを追加しました。TAP割り当ては押下から解放までを保持するためドラッグにも使えます。HOLDとDeckは1回のクリックです。同時に生成できるマウス押下は1つです。停止時はキューに残ったDownの後にUpを送り、押しっぱなしを解放します。

デスクトップ切替では矢印イベント生成時のFn・numeric-pad属性を保持します。無送信テストでSpace＋クリック・進む＋左右クリックの経路と順序を確認しています。OSで実際に画面が切り替わることはこのテストの保証対象外です。

## 2026-10-19 更新

- 戻る／進むボタンの単押しは、デフォルトに明示的な割り当てがなければ「戻る／進む」を送ります。JISとUSのCommand＋角括弧に対応します。押しながら別のボタンを使うレイヤー操作は維持します。対象アプリがこのショートカットに対応している必要があります。
- メイン画面の「ボタンを押して選択」で実際のボタンを押して離すと、現在のレイヤーの割り当て先が選択されます。Actionをドラッグしてください。Escで中止できます。通常レイヤーの左クリック保護は維持します。
- 設定の「Macへのログイン時にRELYRを起動」で自動起動をON/OFFできます。macOSが承認を求める場合はログイン項目で許可します。
- 「前回のエンジン状態を引き継ぐ」をONにすると、有効なまま終了した場合のみ次回再開します。手動で停止した場合は停止状態を維持します。初期値はOFFです。両設定は別々です。
- デスクトップ1〜9はControl＋数字を送ります。対応するmacOSのMission Controlキーボードショートカットを有効にしてください。ウィンドウ自体の移動は、別の「ウィンドウをデスクトップ○へ移動」Actionを使います。
- 「ウィンドウを閉じる（赤い×）」と「アプリを終了（⌘Q）」を分離しました。
- Action一覧は274項目です（単体キーも含むためWindowsの項目数とは直接比較できません）。音量、マイク消音、メディア、明るさ、ブラウザー、Finder、文書編集、標準アプリ、テンキーなどを追加しています。アプリ固有のショートカットとハードウェア機能には対応条件があります。
- 自動テストは実際の入力・Wi-Fi切替・ログイン登録を実行しません。実機の再ログインと全Actionの動作確認は別途必要です。

## マウスジェスチャー

左メニュー「ジェスチャー」から追加し、Action一覧を開いて上下左右・中央へActionをドラッグします。「名前・感度・カーソル固定…」で各定義を変更できます。作成後はレイヤー画面へ戻り、Actionの「ジェスチャー」カテゴリからキー／マウスボタンのTAPへドラッグします。通常の左クリックは保護します。

Windows版と同じ4方向判定、感度3〜100（初期12）、停止110msでの方向実行、押したまま同方向の反復、離した時の残り方向の実行、移動しなかった場合の中央Actionに対応します。設定は押下時に保持します。30秒間動きがない場合やエンジン停止時はキャンセルします。

## マクロ

左メニュー「マクロ」→「新しいマクロ」で作成します。Action一覧から追加欄へドラッグすると手順を追加し、既存の手順へドラッグすると置き換えます。手順クリックで実行前の待ち時間（0〜600000ms）、1回実行／押す／離す、相対・絶対マウス移動を編集します。↑↓で並べ替え、×で削除、ツールバーのUndo／Redoで戻せます。名前変更・複製・削除にも対応します。参照されているマクロの削除や循環参照は拒否します。

「記録…」では物理入力か割り当て後のActionを選び、必要ならマウス移動も記録します。RELYR自身の画面操作と生成イベント、セキュア入力は記録しません。記録には入力の有効化が必要ですが、自動で有効にしません。記録結果は終了後に保存されます。編集画面の「▶ 再生」は直前に使っていた他アプリへ戻してから開始します。切替に失敗した場合は開始しません。停止は「■ 停止」またはControl＋Shift＋F12です（Macの設定によってFnも必要）。緊急停止・スリープ等でも再生をキャンセルし、マクロが生成した押下を解放します。

作成したマクロはActionの「マクロ」カテゴリからレイヤーのTAP／HOLD、Deck、ジェスチャーの各方向へ割り当てできます。マクロ内に別マクロを追加できます（最大16段、展開後10000手順）。実行中は手順のスナップショットを使います。アプリ起動後など、そのアプリの準備待ちが必要な箇所には待機を追加してください。

プロファイル切替Actionと入力無効化Actionも追加しました。プロファイルActionは指定先を手動適用し、自動切替をOFFにします。編集プロファイルを勝手に選び直しません。通常の左クリックなど保護対象は無効化できません。

現時点の制限：記録したホイールは方向Actionへ変換され、元の連続スクロール量・慣性をそのまま再現しません。マウス出力は左・右・中央・戻る・進むの5種類です。記録中の別マクロ再生、ジェスチャー開始手順、Windows固有の記録形式の直接読み込みは未対応です。実機での全アプリ配送・入力記録は自動検証とは区別しています。

### マウスボタンレイアウト

上部でマウスを選び、キーボード右下の「マウスボタンレイアウト」を開くと、そのマウスの図を編集できます。「すべてのマウス」で保存した配置は、個別の配置がない機器で使います。

1. 「ここに置いて検出」にポインタを置き、実物のボタンや左右チルトを操作します。クリックで開始する必要はありません。一覧と配置済みボタンが光り、ポインタを離すと配置編集に戻ります。
2. 右の一覧から中央のマウス図へドラッグします。配置済みボタンはそのまま移動、右下の角で拡大・縮小できます。
3. 「保存」で、選んだマウスの図に反映します。以前保存したパターンは「ひな形を読み込む…」からコピーできます。

「配置から外す」は図から外すだけで、Actionの割り当ては消しません。配置は設定の書き出し・読み込みに含まれます。編集画面では誤作動防止のため入力変換を一時停止し、閉じると直前の状態へ戻します。検出は検出欄にポインタを置いている間のマウス入力が対象です。トラックパッドのスワイプはチルトとして扱いません。外部ソフトがボタンをキー入力へ変換している場合は、その変換を解除して確認してください。

### マウスごとの割り当て

入力を有効にすると、上部のマウス選択欄に接続機種が現れます。特定の機種名をアプリに登録しているわけではなく、Macが機器から読み取った名前を表示します。名前を取得できない場合は「汎用マウス」と識別番号を表示します。後から接続したマウスも一覧へ反映します。「すべてのマウス」は従来の共通設定です。機種を選び、マウスのボタンやマウスレイヤーへActionを割り当てると、その機種だけの設定になります。未設定の項目には共通設定を使います。機種別の項目を削除すると、その機種では未割り当てになります。キーボードの通常キーとアプリ別プロファイルは共通のままです。上部の「編集」と下部の「実行中」には、それぞれ編集対象と最後に操作したマウスが表示されます。

機種の判定にはHID入力監視を使います。同一のメーカーID・製品IDを持つ2台は同じ機種として扱います。これらのIDがない機器でも固有情報があれば識別し、固有情報がまったくない場合は共通設定を使います。接続ポートを識別に使う機器は、ポートを変えると別のマウスとして表示されることがあります。メーカー製ソフトが入力を別のキーへ変換する場合やHID入力を公開しない機器では、自動判定や個別割り当てができないことがあります。上部のマウスを切り替えると、図の配置と機種別Actionが一緒に切り替わります。

## 更新を確認する

メニューバーのRELYR、またはアプリのRELYRメニューから「更新を確認…」を選びます。Mac専用リリースだけを確認します。新しいDMGを取得したらRELYRを終了し、アプリケーションフォルダへ置き換えて起動してください。設定は引き継がれます。自動インストールは行いません。Windows版の更新経路は変更しません。

### 設定も含めて削除する

RELYRの設定から「RELYRをアンインストール…」を使うと、自動起動を解除し、設定・内部バックアップ・キャッシュとアプリ本体をゴミ箱へ移動します。旧保存先も対象です。自分で書き出した設定は削除しません。完全に破棄する場合はゴミ箱の内容を確認して空にしてください。

AppCleanerなど他社ツールの検出対象は保証できません。利用する場合はRELYRを終了し、削除一覧にApplication Support内の io.github.zitan-source.relyr.mac.trial（旧版はRELYR-Mac-Trial）が含まれることを確認してください。アプリ本体だけの削除では設定は残ります。

## トラックパッドへの割り当て

左側の「トラックパッド」を選び、2本指スクロールの上下左右へActionをドラッグします。プロファイルごとに設定でき、未割り当ての方向は標準スクロールのままです。割り当て済みの方向は元のスクロールを抑制し、慣性からActionを実行しません。メニューバー専用設定がある場所では、そちらを優先します。

連続スクロールの方向割り当てはMagic Mouse等にも適用される場合があり、物理デバイス単位の識別ではありません。四隅の1本指タップ・ダブルタップ、端からの2本指スワイプ、3本指／4本指タップと上下左右スワイプ、ピンチイン／アウト、左右回転も割り当てられます。四隅の単独タップは即時実行します。同じ隅にダブルタップも割り当てると、単独タップは2回目を待つため約0.36秒後に実行します。端からの操作は通常スクロールも継続し、同じ方向のスクロールActionとの併用は設定検証で拒否します。

「端をなぞる」では、上端・下端の左右、左端・右端の上下にActionを割り当てられます。1本指と2本指は別々に保存します。図の矢印を選んで右のActionをクリックするか、Actionを矢印へドラッグします。「端の幅」は認識範囲を調整します。中央から始めた入力には端の割り当ては適用されません。

端をなぞる方向は指が動いた向きです。音量は端から最大8.5%以内でなぞり始めると、移動距離に合わせて細かく変わります。調整中はポインタを固定し、指を離すと戻ります。輝度・スクロールは指の移動に合わせて一定の間隔で実行します。アプリ起動などは1回の操作で一度だけ実行します。端に沿うActionとRELYRの通常スクロール割り当てが競合すると、認識中は端のActionを優先します。macOS標準のポインタ移動やスクロールは続く場合があります。

多指入力はmacOSの非公開MultitouchSupport APIを動的に読み込み、既定のトラックパッドを対象にします。OS更新や機器で互換性が変わる場合があります。多指入力の開始に失敗してもキーボード・マウス機能は継続します。macOS標準のクリックやジェスチャーは自動では抑制しないため、四隅のタップ等では標準操作も起きる場合があります。競合する項目は画面内の設定ボタンから確認してください。
