# RELYR for Mac — 試用版 0.2.0

Apple Silicon（M1以降）、macOS 13以降向けの独立したネイティブ試用版です。
Windows版0.1.401の全機能を移植したものではありません。Windows本体・設定・インストーラーには変更を加えません。

## 使える機能

- 通常レイヤーのキー割り当て、キーの長押しリピート
- Spaceを押している間の別割り当て
- Command / Control / Option / Shift を組み合わせるショートカット
- 選択した `.app` の起動（長押ししても1回だけ起動）
- 割り当ての追加・編集・削除とローカル保存
- メニューバー常駐、停止、緊急停止
- プロファイルの作成・複製・編集・削除、前面アプリに合わせた自動切替
- Mac設定のインポート／エクスポートと旧設定のバックアップ
- 非アクティブ型の簡易Deck、名前変更・並べ替え・削除
- 文字列入力（改行・日本語・絵文字）、URL起動、キーからのDeck表示
- Space+A/D/W/Sのサンプル設定をワンクリックで追加

初期設定は空で、毎回停止状態で起動します。入力内容の記録や外部送信はありません。

## ビルド済みZIPを試す

1. `RELYR-Mac-Trial-0.2.0-arm64.zip` をMacにコピーして展開します。
2. `RELYR Mac Trial.app` をアプリケーションフォルダに移します。
3. アプリを開きます。この試用版はアドホック署名で、Developer ID署名・公証は未実施です。macOSに起動をブロックされた場合は、システム設定の「プライバシーとセキュリティ」で、このアプリに対する「このまま開く」を使います。システム全体のGatekeeperを無効にしないでください。
4. 「アクセシビリティを許可…」から、RELYR Mac Trialを許可します。反映されない場合はアプリを終了して再度開きます。
5. レイヤー「Space」、入力「A」、動作「キー」、出力「←」を選んで保存します。
6. 「有効にする」を押し、テキストエディットでSpace単押しが空白、Space+Aが左移動になることを確認します。

ショートカットの例：Space+C → ショートカット / C / Command。
アプリ起動は、動作「アプリ起動」から「アプリを選ぶ…」で指定します。
保存済みの行を選ぶと編集でき、「新規」で追加に切り替わります。

停止は画面の「停止する」、メニューバーの「入力変換を停止」、または **Control + Option + Command + Escape**。
ウィンドウを閉じても常駐します。完全に終了する場合はメニューバーから「終了」を選びます。
Macのショートカットに使う物理修飾キーは出力にも引き継ぎます。

## ソースからビルド

Xcode Command Line Toolsが必要です。未導入ならMacのターミナルで `xcode-select --install` を実行します。
リポジトリのルートで以下を実行してください。

```sh
bash macos/build.sh
open '.verification/macos/RELYR Mac Trial.app'
```

スクリプトは入力を生成しない状態遷移・保存テスト、警告をエラーにしたコンパイル、
Apple Silicon上での画面起動テスト、アドホック署名検証を行います。
アプリとZIP、SHA-256は `.verification/macos/` に生成します。
GitHub Actionsの `macOS trial` でも同じスクリプトを実行できます。

## 試用版の制限

- マクロ、マウス割り当て、ジェスチャー、自動起動、自動更新は未実装です。
- Deckは1枚・最大48ボタンです。位置の永続化、複数Deck、自由配置、モニター表示、ファイルのドラッグ＆ドロップには未対応です。
- Windows設定のインポート・共有は未対応です。Mac設定は別ファイルに保存します。
- キー名はUS配列の物理位置を基準とします。JISの記号キーは表示と異なる場合があります。英数／かなキーは選択できますが、IMEとの挙動は実機確認が必要です。
- Spaceと修飾キー自体は割り当て元に指定できません。CapsLockレイヤーは未対応です。
- Spaceレイヤーに割り当てがある場合、単独Spaceは離したときに1回入力します。長押しで連続空白を入力するにはSpaceレイヤーを無効にしてください。
- Spaceと未割り当てキーを組み合わせると、そのSpaceを先に復元し、Spaceを離すまで通常入力になります。通常レイヤーの割り当てはこの最初の未割り当てキーには適用しません。
- Space待機中に修飾キーやマウス操作を行った場合もSpaceを復元します。Command+Spaceなど修飾キーを先に押す組み合わせはそのまま通します。
- パスワード欄などのセキュア入力には対応しません。検知時、スリープ時、セッション切替時、入力監視の中断時は停止し、手動での再開が必要です。
- ショートカットはキーイベントに修飾フラグを付けて出力します。通常のアプリのショートカットが対象で、独自の低レベル入力を読むアプリでの互換性は未確認です。
- 実際のキーボード・IME・対象アプリとの動作確認は、自動テストとは別に必要です。

## 設定ファイルと復旧

保存先：`~/Library/Application Support/RELYR-Mac-Trial/configuration.json`

保存は検証後にアトミックに行います。設定破損・未対応バージョンを検出した場合は上書きせず、
入力変換と編集を無効にします。アプリを終了してファイルをバックアップし、別名へ移してから再起動すると空の設定で始められます。
設定変更中に押されているキーは、押した時点の出力先へUpを送ります。

## 実機チェックリスト

以下は手元のMacで確認する項目です。自動テストの成功だけで合格とはしません。

- [ ] 権限なしでは入力を変換せず、許可後に有効化できる。
- [ ] Space短押し・長押し→離すと空白が1つ。未割り当ての次の文字より前に空白が入る。
- [ ] Space+Aの長押し、A→Spaceの順／Space→Aの順で離す操作でキーが残らない。
- [ ] 通常A→Bと、Space+C→Command+Cが対象アプリで動く。
- [ ] アプリ起動は短押し・長押しのどちらも1回。
- [ ] 通常入力、Command+Space、日本語変換、英数／かなが意図どおり。
- [ ] 保存・再起動後も割り当てが残り、入力変換は停止状態。
- [ ] 緊急停止、メニュー停止、終了、スリープ後に通常入力へ戻る。
- [ ] 同じ出力キーへ複数キーを同時に割り当てた操作や、物理出力キーとの同時押しを評価する。未検証の組み合わせは常用しない。

## 実装と参考資料

Swift / AppKit / Core Graphicsの小規模なネイティブ実装です。既存のWindows用 `.csproj` はそのままです。
`LayerMachine.swift` はOS APIを呼ばない入力状態機械、`InputEngine.swift` はイベントタップ、
`Configuration.swift` は設定検証・移行・保存、`AppDelegate.swift` は画面と常駐メニュー、
`DeckController.swift` は非アクティブ型Deckを担当します。

## 0.2.0の追加機能

### サンプルから試す

「サンプル追加」で、現在編集中のプロファイルにSpace+A/D/W/S → 左/右/上/下を追加します。
既存の同じ割り当ては上書きしません。「手動使用」で同じプロファイルを選択してから有効化してください。
自動切替中は、実際の前面アプリに応じたプロファイルを使います。画面の「実行中」で確認できます。

### プロファイル

- 「編集」は画面に表示する設定、「手動使用」は実際に使う設定です。編集対象を選ぶだけでは実行対象は変わりません。
- 「新規」で空のプロファイル、「複製」で現在の割り当てをコピーして作成します。
- 「対象アプリを追加…」で `.app` を登録し、「アプリに合わせて自動切替」をオンにすると、そのアプリが前面になったときだけ切り替わります。
- 未登録アプリと、特に登録していないRELYR自身は「標準」を使います。マウスが乗っているだけのアプリでは切り替わりません。
- 同じアプリを複数プロファイルに登録することはできません。「関連付けを解除」で現在のプロファイルの関連付けをすべて解除できます。
- 押している途中で切り替わっても、すでに押されたキーのUpは元の出力先へ送ります。
- プロファイルの削除では、その割り当てを参照するDeckボタンも削除します。標準プロファイルは削除できません。

### Deck

保存済みの割り当てを選び「Deckへ追加」→名前を入力→「Deckを表示」で開きます。
タイトルバーをドラッグして移動でき、右クリックで名前変更・前後への移動・削除ができます。
元のキー割り当てを変更するとDeckにも反映され、削除すると関連ボタンも取り除かれます。

Deckは各ボタンが登録元のプロファイル・割り当てを参照します。実行プロファイルの自動切替でボタンの内容は変わりません。
Deckから削除しても元のキー割り当ては残ります。キーの「動作」で「Deck表示／非表示」を選べば、Space+任意キーで呼び出せます。

**先に操作したいアプリのウィンドウをクリックしてから、Deckを押してください。**
Deckはアプリのフォーカスを奪わず、その時点の前面アプリへ実行します。
入力変換が停止中ならボタンも停止します。同じ出力キーを押したままの場合は、キーを離してから押し直してください。

### 文字列・URL

「動作」で「文字列入力」または「URLを開く」を選び、「内容を編集…」から値を入力して保存します。
文字列は最大4096 UTF-16文字、URLは `http://` / `https://` のみです。
クリップボードを置き換えず、短いUnicodeイベントに分けて送ります。
送信中のアプリ切替、別のキー入力・クリック・修飾キー操作、停止、セキュア入力で残りの送信を中断します。
途中まで入力済みの文字は自動で取り消しません。独自入力処理のアプリでの文字列互換性は実機確認が必要です。
内容はローカル設定ファイルに平文で保存され、書き出した設定にも含まれます。

### 設定の持ち運び・復旧

- 「設定を書き出す…」でMac版専用のJSONを保存します。「設定を読み込む…」は内容を検証し、確認後に現在の設定を置き換えます。
- 読み込み前のファイルは同じ設定フォルダ内の `configuration.before-import-<ID>.json` にバックアップします。
- 読み込み後は入力変換を停止します。内容を確認してから再度有効にしてください。
- 0.1.0の設定も読めます。最初の保存時に旧形式の元ファイルを `configuration.v1.backup.json` として保存します。
- 0.2.0の設定は0.1.0へ戻して読み込めません。戻す場合は0.1.0のバックアップを使ってください。
- 不正な参照、重複、未対応バージョン、1MBを超えるファイルは拒否します。Windows版のJSONには対応しません。
- 現在の設定が破損していても、正常な書き出しファイルを読み込んで復旧できます。破損した元ファイルも保持します。

### 追加の実機確認

- [ ] アプリ切替時に「実行中」は変わり、編集対象は変わらない。
- [ ] キーを押したまま別アプリへ切り替え、キーを離しても入力が残らない。
- [ ] Deckを押しても対象アプリのフォーカスを奪わず、期待したショートカットが実行される。
- [ ] Deckの名前・順序・参照が保存され、元の割り当て編集がすぐ反映される。
- [ ] 日本語・改行・絵文字の文字列が正しく入り、別アプリへの切替や緊急停止で残りが止まる。
- [ ] URLが既定のブラウザで1回だけ開き、キー長押しでタブが増え続けない。
- [ ] 書き出し→読み込みと0.1.0からの移行で、設定とバックアップが残る。
